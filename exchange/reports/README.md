# reports/ — convention

1. Builder outputs land here: what was built, what was verified, what failed, what was left undone.
2. Naming: `YYYY-MM-DD_<LANE>_<type>_<name>.md` — e.g. `2026-08-02_HEPHAESTUS_report_exchange-v1-build.md`.
3. `<LANE>` is the authoring lane in caps; `<type>` is one lowercase word (report, audit, verify, fixup).
4. One file per run. A re-run gets a new file, never an overwrite of the old one.
5. Reports are evidence of work, not the work itself — deliverables live where the work order named them.
