## Method

**Before.** Nine agents each read one span of the pre-collapse file (commit `a2b69cf`) and enumerated every distinct normative rule at maximum granularity — an obligation embedded in a justification counts, an exception counts, a required table column counts. Each rule was recorded with its line, its kind, and its *load-bearing detail*: the exact value, path, command or enumerated set that would be lost if only the one-sentence statement survived. None of the nine knew what the restructure would look like.

**After.** Ten further agents were given the before-list in batches and the three post-collapse documents, and told to hunt for losses rather than confirm the work. Four verdicts were available: SURVIVED, SURVIVED_WEAKENED (the obligation is there but a load-bearing specific is gone), RELOCATED (present, but in CASELAW or LEDGER_APOLLO), LOST.

## What this census does NOT prove

It proves every *rule* survived. It does not prove the restructure is *better* — that is an operator judgment, and the honest case for it is that a lane now reads §0 plus one section instead of 64 KB, and that a fact asserted twice with different values is now findable by fixture rather than by accident. It also does not prove the granularity is right: the before-census counted 422 rules where a reader would say perhaps eighty, because it was told to split aggressively. The number is a tripwire, not a measurement of how much law this project has.
