### Three build defects found and fixed during Phase I

1. **F-AN-4 tripped on its own documentation.** The raw-text scan flagged `__init__.py: open( at offset 916` — a docstring *describing* the ban. Fixed by tokenising and dropping `STRING`/`COMMENT` tokens, so the invariant tests executable code rather than prose.
2. **ATR warm-up is `length-1`, not `length`.** `true_range` defines index 0 as `H−L` rather than NaN, so the Wilder average completes one bar earlier than RSI, which loses a bar to `diff()`. `CONVENTIONS` was already correct; the test expectation was wrong and was corrected, with the reason recorded inline.
3. **F-AN-14 failed by exactly 1 ULP** (max abs 3.6e-12) — numpy pairwise summation vs pandas `groupby` accumulation on volume. Since the fixture demands *byte-identical* agreement with a pandas reference, `resample_ohlcv` now uses the same pandas reduction rather than negotiating a tolerance. Lowering that bar would have contradicted the byte-identity standard this project applies everywhere else (F-SIG/F-BYTE/F-A-BYTE).

### Two deliberate spec reconciliations, recorded not buried

- **F-AN-4 vs F-AN-5.** I-A/F-AN-4 forbid I/O and scan for `open(`; F-AN-5 requires `analytics_sha()` to hash the package's own sources. Reconciled by making the self-hash a **provenance** function that uses `pathlib.Path.read_bytes()`, never the builtin. No function that returns a number reads anything.
- **`resample_ohlcv` placement.** §I.1's layout lists no resample module, but §I.3 pins the convention and F-AN-14 tests it. Placed in `structure.py` rather than inventing a module outside the declared layout.

**The v1.1 brief computed its 4h and 12h layers over one bar more than the native estate contains at the published `last_bar_utc`** — consistently, across every asset and both timeframes. Extending the load window by a full bar step does not produce that bar, so it is not a slicing error on my side: the bar is not in the native 4h/12h klines at all. The most likely mechanism is that the brief builds those frames by resampling a lower timeframe, which yields one extra partial bucket for the in-progress period.

If that is what happened, the published 4h/12h/1d values — RSI, ATR, and everything downstream including the ATR percentile and the weekly momentum vote — were computed including an **unclosed bar**. That is exactly the condition §II.12 F-B17 exists to forbid, and §II.10 G1 exists to correct. Resolving it is Phase II work, but it must be ruled on *before* the brief is rebuilt on `analytics/`, because the rebuild would otherwise either silently change accepted numbers or silently preserve the defect.

Per §I.6 — *"Any mismatch halts adoption of that recipe"* — and §X — *"Any FAIL → halt, report, no partial adoption"* — I stopped here and did not begin Phase II.

### The one precise question

> **Is the v1.1 brief's extra 4h/12h bar an in-progress bucket produced by resampling from a lower timeframe — and if so, should BRIEF-2 reproduce v1.1's published numbers (preserving the unclosed bar so F-AN-8 passes as written), or drop it to satisfy F-B17's closed-bar rule and accept that the 4h/12h/1d published values change?**
